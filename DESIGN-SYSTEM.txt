TYPE ROLES

Title: Oswald 700, 36–72px fluid, line-height 1.08, uppercase, balanced wrapping.
Section heading: Oswald 700, 28–32px fluid, line-height 1.2, uppercase.
Item heading: Oswald 400, 20px, line-height 1.3, uppercase. Category and accordion titles should share this role when implemented.
Body: Source Sans 3 400, 16px, line-height 1.5.
Lead: Source Sans 3, 18px, line-height 1.65 (normalizes the former 17.6px intro).
Compact heading: Source Sans 3 600, 18px, line-height 1.4; shared by page ticket names and attendee headings.
Supporting text: 14px, line-height 1.5, including attendee-field descriptions. Small labels: 12px, weight 600, uppercase, 0.06em tracking.
Button: Oswald 700, 14px, line-height 1.5, uppercase, 0.1em tracking.
Typography tokens own responsive sizing: title and section roles scale fluidly; item, lead, body, supporting and label roles remain steady at all widths. Components and native adapters keep the same role across breakpoints. Use bckfc-supporting-text for supplementary copy, including the ticket purchase reminder and registration deadline. Native page ticket names use the lead size; modal ticket names adopt the shared item-heading role; the modal dialog title uses the section size at every width.
Semantic heading level is independent of visual role. No global rule that makes every h2 look like a section title. A title class can go on Avada's Title wrapper; the known inner .fusion-title-heading receives the same role without doubled margins. Keep element typography overrides empty so CSS can own the result.

OWNERSHIP BOUNDARY

Avada owns page structure: section placement, full-width versus constrained containers, native columns and spacing between those columns. The design system owns shared appearance: colors, typography, buttons, borders and consistent section padding. Our custom components own their internal layout and responsive arrangement, such as Highlights columns and Times and Locations stacking.

Shared appearance classes must not silently change native column widths, spacing or arrangement. bckfc-section supplies section padding and heading spacing, not a column-spacing reset. bckfc-accordion styles the accordion without changing its surrounding columns. Configure native structural settings through Avada and carry them in saved/exported containers; constructing a container from scratch still requires that configuration.

The ticket adapter has explicit integration exceptions: scoped column-margin resets, stacking corrections, and modal sizing/scrolling. These are not appearance-only rules. Keep such exceptions scoped to the adopted component, retain only verified needs, and document their reason beside the rule. Do not generalize them into shared section classes.

SPACING AND LAYOUT

Base spacing steps: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80px. Use the corresponding space tokens. Border widths, icon sizes and optical offsets are not spacing-scale violations. A new exception must have a visual reason; do not add a token for every one-off number.

Starting layout convention: 8px outer mobile gutter (user preference); one owner for the gutter, no nested container/column padding accumulation. Ordinary section interior padding is 24px vertical / 8px horizontal on mobile, and 32px on all sides on desktop. Categories, Times and Locations, and native authored sections share these declarations in foundations.css. Native section gutters belong to the constrained inner Avada row; custom components already live inside that row. Never put the gutter on both. Tickets shares the horizontal gutter but deliberately retains 40px mobile / 48px desktop vertical padding; the hero and compact highlights retain their own density. Section-heading-to-content gap 24px. Closely related items use 8–12px gaps; independent groups 24–32px. Adjacent full-width sections have no outer gap. Avada owns site width and responsive column settings. Validate the narrow gutter against the actual header before treating it as final.

Use 768px as the initial content layout transition when CSS needs one, matching v1. Do not assume Avada's configured responsive breakpoint matches it: reconcile during actual layout construction. Fluid typography does not require a second stack of breakpoint overrides. Avoid fixed content heights, forced date line breaks, arbitrary negative margins and global overflow clipping.

CONTROLS, ICONS AND ALERTS

Buttons: minimum 48px height, 12px/24px padding, 12px icon gap, 4px radius. Primary, outline on light, outline inverse on dark. Keep keyboard focus visible and honor reduced-motion preference. Use a real disabled button for a disabled action; CSS is not interaction enforcement. Coming Soon is a message in the header, not a disabled link or event purchase switch.

Icons: consistent outlined family, 20px beside text, 24px for compact highlights, 48px only when a location illustration needs emphasis. Use the same icon source/family per component; do not mix glyphs, emoji and drawn variants. The header uses shared Lucide SVG assets in assets/icons, with their license included.

Alerts: carry forward the optional icon + message concept. Keep message text readable, color/icon supplementary, and use a semantic role only when its behavior warrants it. The header includes its optional alert in the same element settings form.

The element uses a PHP markup partial, not a WordPress event template override. Event metadata and checkout behavior remain in Tools.

Use bckfc-button on the actual anchor/button; bckfc-button--outline adds the light outline, and --inverse is combined with --outline for dark surfaces. These are intentionally not auto-applied to Tribe, WooCommerce or every Avada button. The native ticket heading and purchase controls are explicit adapters in foundations.css and buttons.css; event-tickets.css owns their surrounding layout and verified native conflicts.

Shared layouts contain structure, not event-specific images/text/URLs. BCKFC Tools remains responsible for event facts and behavior; the child theme handles appearance. Keep production transport simple: theme files plus separately exported/imported Avada content. Never copy parent theme templates just to recover the old header.
